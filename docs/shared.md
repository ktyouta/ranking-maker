# Ranking Maker 共通設計

## UI / UX 方針

### トーン

- ポップ＆カジュアルを採用する。明るい配色と丸みのある形状を基調に、「ランキングを作るのが楽しい」という体験価値を優先する
- ユーザーが入力したタイトル・項目名・メモは装飾を加えず素直に表示する。ポップな装飾はヘッダーやボタンなど UI の骨格側に留め、コンテンツと衝突させない
  - シリアス寄りのお題（例: 後悔した買い物ランキング）でも成立させるための唯一の歯止め

### ナビゲーション設計

PC・モバイル共通で「ヘッダー＋ハンバーガー→ドロワー」に統一する。常時表示の固定サイドバーは採用しない。

- **ヘッダー**: 画面上部に固定。左にハンバーガーアイコン、中央〜左寄せにアプリタイトル、右端にユーザーアイコン。アクセントカラーでソリッド塗り、アイコン・文字は白系
- **ドロワー**: ハンバーガータップで開く。背景は `#F2FAF9`（ベース背景色）、開く方向と逆側の角に控えめな丸み（`rounded-lg`）を付与。既存の `frontend/src/components/ui/drawer/drawer.tsx` を `side="left"` で流用
  - 項目例: ランキング一覧・作成・マイページ・ゴミ箱・ログアウト

### ランキング項目のレイアウト

全項目を「カード」として統一する（罫線のみの素のリスト行は併用しない）。上位3件と4位以降は、別レイアウトを持たせるのではなく、サイズ・影の強さ・バッジの装飾度合いだけを変える地続きの設計とする。

- **上位3件（表彰台）**: 大きめの影・大きめのパディング。金・銀・銅の縁取り／バッジ付き
- **4位以降**: 影は残すが薄く小さめ（`shadow-sm`程度）にし、パディング・行間を詰めてコンパクトにする
  - 影自体はレイアウトの高さに影響しないため、影の有無ではなくパディング・行間の調整で密度を確保する
- `items` 配列に件数の上限はない（`min(1)`のみ）ため、項目数が多いランキングでもスクロール量が破綻しないことを前提にレイアウトする

### 禁止事項

- 順位カラー（金・銀・銅）とアクセントカラーを混色・近似させない（順位演出の視認性を損なうため）
- ユーザー入力コンテンツ（タイトル・項目名・メモ）を装飾・加工しない
- 常時表示される大面積（サイドバー全面等）への単色ベタ塗りは避ける（視覚疲労のリスク）。ベタ塗りは面積の小さいヘッダーに限定する

### 検討して見送った案

**全体テイスト**
- ミニマル＆エディトリアル: どんなお題でも破綻しない懐の深さはあるが、エンタメ性が伝わりにくい
- 骨格ミニマル＋演出のみポップ: 線引きルールを個人開発で維持し続けるコストが重い

**ナビゲーション**
- PC左サイドバー固定: PC/モバイルでレイアウトが二重化し、常時表示エリアが管理画面的で硬くなる
- モバイル下部タブ: カジュアル系の定番だが、タブに載せる項目を3〜5個へ絞る優先順位づけが要る

**アクセントカラー**
- 紫（Violet）: 金・銅と対照的で順位演出は引き立つが、「攻めすぎ」と判断し不採用
- 青（Blue）: 失敗しにくい定番色だが、個性が出しにくい
- 緑（Green）: ポジティブな印象だが「成功・完了」を示す状態表示色と意味が紛れる

**ランキング項目のレイアウト**
- 全項目を同じ重さのカードにする: 項目数が多いランキングで縦に間延びし、スクロールが辛くなる
- 4位以降を罫線のみの素のリスト行にする: 色・丸みがなくなり、ポップというテイストと矛盾する
