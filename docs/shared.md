# Ranking Maker 共通設計

## UI / UX 方針

### トーン

- ポップ＆カジュアルを採用する。明るい配色と丸みのある形状を基調に、「ランキングを作るのが楽しい」という体験価値を優先する
- ユーザーが入力したタイトル・項目名・メモは装飾を加えず素直に表示する。ポップな装飾はヘッダーやボタンなど UI の骨格側に留め、コンテンツと衝突させない
  - シリアス寄りのお題（例: 後悔した買い物ランキング）でも成立させるための唯一の歯止め

### カラーパレット（テーマ選択制）

ユーザーが「teal（現状）／ラベンダー／ピーチ／ダークモード」の4択からテーマを選べる（アクセントカラー×ライト/ダークの掛け合わせではなく、フラットな4択）。1位/2位/3位のランクカラー（Gold/Silver/Bronze）はテーマに関わらず固定とし、順位演出の視認性を優先する。

| 用途 | teal（現状・デフォルト） | ラベンダー | ピーチ | ダークモード |
|------|------|------|------|------|
| 背景（ベース） | `#F2FAF9` | `#F5F3FF` | `#FFF4EF` | `#111827`（gray-900） |
| 背景（カード・ドロワー本体） | `#FFFFFF` | `#FFFFFF` | `#FFFFFF` | `#1F2937`（gray-800） |
| アクセント（ヘッダー・主要ボタン等、小面積） | `#0F9E93` | `#7C6FE0` | `#E8663D` | `#22D3EE`（cyan-400） |
| アクセント（ホバー・強調） | `#0B7A72` | `#6759CC` | `#C94F2A` | `#67E8F9`（cyan-300） |
| アクセント（ボタン・バッジ・サイドバー等、単色の塗りつぶし全般） | `#0F9E93`（アクセントと同値） | `#7C6FE0`（同値） | `#E8663D`（同値） | `#164E63`（cyan-900） |
| テキスト（メイン） | `#12302E` | `#241F3D` | `#33241D` | `#F3F4F6`（gray-100） |

| 罫線 | `#D9EEEB` | `#E6E1FF` | `#F3DBCB` | `#374151`（gray-700） |

| ランクカラー（全テーマ共通） | カラー |
|------|--------|
| 1位（Gold） | `#B4881A` |

| 3位（Bronze） | `#A2653A` |

実装は `frontend/tailwind.config.js` の各色を CSS 変数参照にし、`frontend/src/index.css` 側で `[data-theme="teal"|"lavender"|"peach"|"dark"]` ごとに変数値を定義する方式（`<html data-theme="...">` の切り替えのみでビルド不要に反映）。詳細は `docs/theme-selection/plan.md` を参照。

ラベンダー／ピーチのアクセント以外の色（背景・罫線・テキスト）は、teal 側の「アクセントの色相を保ったまま明度・彩度を振った関係性」を踏襲して機械的に導出した値であり、実機確認前の暫定値。見た目を確認しながら微調整する前提とする。

**ダークモードは上記の機械的導出をやめ、参考実装（別リポジトリ `todo-react-hono-rpc`）の値をそのまま踏襲する**（背景はteal色相にせず、ニュートラルなgray-900/800 + アクセントはcyan-400/900のみ）。理由: 当初「アクセントの色相を保ったまま明度を振る」方式で `#0B1716` 等のteal寄りの暗い背景を機械導出したが、実機確認で参考実装と系統が違いすぎる（参考実装は背景がニュートラルグレーでアクセントだけが際立つ配色）と判明したため。

**アクセントの「塗りつぶし」と「文字・細線」を分けた理由**: 実機確認で、ダークモードのサイドバーに続き、検索ボタンやカードのアイコンバッジ等の**単色塗りつぶし**にも明るいシアン（`#2FD6C7`）がそのまま使われており、暗い画面の中で浮いて見える問題が発覚した。参考実装（別リポジトリ `todo-react-hono-rpc`）を確認したところ、ボタン・バッジ・サイドバーを含む「塗りつぶし」用途は例外なく `bg-cyan-500 dark:bg-cyan-900` のようにダーク時は暗く沈め、`text-cyan-400`のような文字色・細いボーダーのみ明るさを保つ、という一貫した使い分けをしていた。これに倣い、「塗りつぶし」用途はアクセントと別トークン（暗い値）に統一し、文字・細いボーダー・薄いopacityの装飾は通常のアクセント（明るい値）のまま残した（ライト3テーマではどちらも同値のため見た目に変化なし）。

### ナビゲーション設計

PC・モバイル共通で「ヘッダー＋ハンバーガー→ドロワー」に統一する。常時表示の固定サイドバーは採用しない。

- **ヘッダー**: 画面上部に固定。左にハンバーガーアイコン、中央〜左寄せにアプリタイトル、右端にユーザーアイコン。アクセントカラーでソリッド塗り、アイコン・文字は白系
- **ドロワー**: ハンバーガータップで開く。背景は `#F2FAF9`（ベース背景色）、開く方向と逆側の角に控えめな丸み（`rounded-lg`）を付与。既存の `frontend/src/components/ui/drawer/drawer.tsx` を `side="left"` で流用
  - 項目例: ランキング一覧・作成・マイページ・ゴミ箱・ログアウト

### ランキング項目のレイアウト

全項目を「カード」として統一する（罫線のみの素のリスト行は併用しない）。上位3件と4位以降は、別レイアウトを持たせるのではなく、サイズ・影の強さ・バッジの装飾度合いだけを変える地続きの設計とする。

- **上位3件（表彰台）**: 大きめの影・大きめのパディング。金・銀・銅の縁取り／バッジ付き
- **4位以降**: 影は残すが薄く小さめ（`shadow-sm`程度）にし、パディング・行間を詰めてコンパクトにする
  - 影自体はレイアウトの高さに影響しないため、影の有無ではなくパディング・行間の調整で密度を確保する
- `items` 配列に件数の上限はない（`min(1)`のみ）ため、項目数が多いランキングでもスクロール量が破綻しないことを前提にレイアウトする

### 禁止事項

- 順位カラー（金・銀・銅）とアクセントカラーを混色・近似させない（順位演出の視認性を損なうため）
- ユーザー入力コンテンツ（タイトル・項目名・メモ）を装飾・加工しない
- 常時表示される大面積（サイドバー全面等）への単色ベタ塗りは避ける（視覚疲労のリスク）。ベタ塗りは面積の小さいヘッダーに限定する

### 検討して見送った案

**全体テイスト**
- ミニマル＆エディトリアル: どんなお題でも破綻しない懐の深さはあるが、エンタメ性が伝わりにくい
- 骨格ミニマル＋演出のみポップ: 線引きルールを個人開発で維持し続けるコストが重い

**ナビゲーション**
- PC左サイドバー固定: PC/モバイルでレイアウトが二重化し、常時表示エリアが管理画面的で硬くなる
- モバイル下部タブ: カジュアル系の定番だが、タブに載せる項目を3〜5個へ絞る優先順位づけが要る

**アクセントカラー**
- 紫（Violet）: 当初「攻めすぎ」と判断し不採用としていたが、テーマ選択機能の追加に伴いラベンダーとして採用に方針転換（単色固定ではなくユーザーが選べる形にしたことで、単色運用時の「攻めすぎ」懸念が後退したため）
- 青（Blue）: 失敗しにくい定番色だが、個性が出しにくい
- 緑（Green）: ポジティブな印象だが「成功・完了」を示す状態表示色と意味が紛れる

**テーマ選択のピーチとBronzeの近似について**
- ピーチのアクセント（`#E8663D`）とランクカラーのBronze（`#A2653A`）はどちらも暖色系のオレンジ〜茶系で色相が近い。禁止事項（順位カラーとアクセントカラーの混色・近似回避）に抵触しないか、ピーチテーマでの実機確認時に要チェック

**ランキング項目のレイアウト**
- 全項目を同じ重さのカードにする: 項目数が多いランキングで縦に間延びし、スクロールが辛くなる
- 4位以降を罫線のみの素のリスト行にする: 色・丸みがなくなり、ポップというテイストと矛盾する
